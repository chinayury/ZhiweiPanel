# 智维面板 ZhiweiPanel 借鉴与修复记录（v0.5.1）

> 产出时间：2026-11-23　｜　patch 轮　｜　前几轮见 [RESEARCH-BORROW-v0.5.0.md](RESEARCH-BORROW-v0.5.0.md)
> 本轮：**清偿一笔挂了三版的文档债**——README 已知限制 #14（`-backup-dir` 只建目录不生效）。

## 一、来源与依据

`-backup-dir` 不生效是 v0.2.0 引入备份功能时留下的债：flag 只参与启动时的
MkdirAll，备份落盘路径硬编码 `<data>/backup`。此后 README 已知限制一直挂账
（原 #16 → 本轮前的 #14），三版迭代里都没排到。

实施前照例先读实现，确认了三处落盘/清理点（`BackupSite` / `BackupDatabase` /
`PruneOrphanFiles`）和一处**遗留死代码**（`service.backupRoot` 字段 =
`<data>/backups`，只在删站清理里被拼进一个没人写入的路径——本轮不动它，
与本次修复无关，留待后续清理轮处理）。

## 二、设计与取舍

| 决策 | 理由 |
|------|------|
| flag 空 = 保持 `<data>/backup` 历史默认 | 老部署的备份记录（DB 里存的是绝对路径）都指向那里；改默认值等于让旧记录的下载/恢复失效。**向后兼容优先于"修正默认值"** |
| 显式设置 = 新备份写新目录，旧记录/文件不动 | 满足 flag 的原始意图（自定义备份位置）；已产生的备份是历史事实，不能悄悄搬家 |
| 切换后旧目录不再被孤儿清理扫描 | 在 CHANGELOG 与 USAGE 里显式写明，需要迁移手工挪——比"静默把旧文件搬过去"可预期 |
| Service 层新增 `SetBackupDir` / `BackupRoot`，backup 包三处改走 `BackupRoot()` | 与 `DataDir()` 同款访问器形态；不传 flag 时行为与历史逐字节一致（符合"新增参数默认值与历史行为兼容"的硬约束） |

**测试**：`internal/service/backup_dir_test.go` 锁死三段语义（默认 / 显式生效 /
空值不覆盖）。

## 三、本轮其余事项

- 测试机 SSH 22 不可达已持续超过 48 小时（服务器存活、其它端口正常）——
  v0.4.0/v0.5.0 的部署验证继续挂起，恢复脚本 `phase-h4-run.ps1` 就绪。
- 本机内存压力已影响 PowerShell 运行时（模块加载失败），API 轮询改用 Node
  内置 fetch 的脚本（tmp/zw-maint/）。

## 四、一句话结论

> 挂账三版的"参数不生效"终于清偿。修法上最有价值的一条是**默认值不动**：
> 兼容性优先，让真正想要自定义位置的用户显式付费（自己迁移旧文件），
> 而不是让所有老部署为一次"修正"买单。
